# Entry #3
Chapter 4, _Knowing What To Do: Constraints, Discoverability, and Feedback_, talks about how constraining the user can aid the clarity of a design. One of the best ways to help the user not make
mistakes when trying to use something is by not allowing those mistakes to be physically possible. The example the book brings up is with batteries. There are a wide array of different types of
batteries, different devices asking for a specific type. Despite this, it is relatively easy to understand which batteries _don't_ work because of the different sizes. Try using a double A battery
in a device for a triple A battery and it simply won't fit. Try using a triple A battery in a double A battery slot and it will be apparently clear that the battery is way too small. Constraints
are a quick way to allow the user to use process in elimination to figure out what is it that they need to do in order to use a device.
